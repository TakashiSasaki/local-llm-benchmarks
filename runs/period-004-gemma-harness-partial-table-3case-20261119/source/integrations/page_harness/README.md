# Local page-reading harness

An experimental local harness between llama.cpp and the user's SearXNG and Crawl4AI MCP endpoints. The model can search, open a search-result URL, search within saved text, and reread a bounded character range. Crawl4AI's `md` and `read_document` APIs are used to assemble the complete server snapshot into a local UTF-8 JSON file; IDs, offsets, source URL and SHA-256 remain in that file. A too-large or inconsistent snapshot is rejected instead of silently truncated. Page text is untrusted; the model is instructed not to follow instructions in it.

The default compaction policy renders the actual chat template before each model request. When its input reaches half of the 65,536-token window (32,768), the same local model summarizes eligible middle turns in a separate inference call. The original system and user messages, the first assistant/tool turn, the two most recent complete assistant/tool turns, and any tool result not yet shown to the model are kept. Complete turns are removed together so tool-call IDs are not orphaned. The locally saved original requests, responses and tool results remain unchanged; during the active run `read_archived_turn` can retrieve an archived turn in bounded pieces. Restart/resume of an interrupted run is not implemented.

The summary uses Thinking OFF, temperature 0 and at most 2,048 output tokens; normal research responses use Thinking ON and at most 8,192 output tokens. Before replacing any turns, the runner records the summary request/response, requires a nonempty normal-stop answer, and checks that the resulting rendered prompt is shorter. A failed, truncated or ineffective summary stops the case as incomplete without an automatic retry or discarding the original history. Summaries are lossy and untrusted: they can omit or change facts, and neither the token reduction nor the ledger proves semantic fidelity. If protected content dominates, reaching half the window does not guarantee compaction can reduce it. The runner still reserves 32 slots, clips the next output allowance to the remaining window, and stops incomplete when there is no room. Input counting includes one empirically observed BOS token for the tested b11960 Gemma template; revalidate that adjustment for other runtimes or templates. The 65,536 context setting itself is unchanged.

Literal in-page search falls back to ranked lexical candidates when there is no exact match; candidates are explicitly marked as approximate, and include offsets and the closest preceding heading. It is not semantic search and can miss or rank the wrong passage. `page_outline` paginates long heading lists. Each case has `ledger.json`: the original question, optional model-added requirements, and automatically recorded page ranges with URLs, offsets, page/range SHA-256 and whether the range was shown to the model. The model can use `add_requirement`, `update_requirement`, `inspect_ledger` and `read_evidence`. A requirement is either open or a model-proposed candidate; linking a candidate requires an existing evidence ID already shown to the model. After compaction, up to two linked passages (at most 3,200 characters total) are copied from hash-checked saved pages into the model's context; additional or invalid entries are counted explicitly. `read_evidence` rereads an exact saved range by ID. This validates provenance only, not whether the quotation or claim is relevant or correct. The compact ledger is supplied in subsequent requests, with an explicit count of omitted evidence entries. The full ledger and original page snapshots remain local, including when the answer must contain only a number. The runner reports remaining per-tool budgets and turns to the model, and refuses to repeat an identical failed search/page request within a case; it does not retry inference automatically.

Approximate matches now distinguish words in the shown excerpt from words elsewhere in the larger ranking window, and retain more surrounding context. Longer excerpts consume more input tokens and remain approximate. Empty or unseen evidence IDs are rejected with a bounded list of previously shown candidates; candidate relevance is not automatically established. Explicit phrases such as `as of April 2025` are retained as temporal reminders, but no publication-date filter can prove a historical claim. Citation audits resolve ledger IDs and page IDs, mark unknown or unseen references, and allow strictly numeric answers without an inline URL. These are exposure checks, not factual verification. Earlier saved runs are unchanged.

The runner starts/stops only its own Gemma MTP server. It uses the existing local command file `.local/humaneval-plus-20261117/gemma-mtp-fullctx-command-20261118.json` and the existing BFCL virtual environment. It sends model-generated search queries to the configured SearXNG MCP and selected URLs to Crawl4AI; those services may make external requests. It accepts only URLs returned by search and checks locally resolved addresses are public before requesting a crawl. Redirect handling is performed by the remote Crawl4AI service, not independently verified by this client. Authentication, access and rate-limit errors stop the run; failed cases are not retried automatically. The default live experiment uses two public questions, and each case has explicit search, page and turn budgets. The 12-case study stored its earlier 20-turn/four-page limits and earlier source snapshot; the updated defaults are 30 turns and six page opens. Fresh runs automatically save a source snapshot; previous runs retain their actual historical code and conditions.

For a new authorized trial, use a new run ID and pass one or more public questions.

```powershell
& .local/bfcl-official-venv/Scripts/python.exe -B scripts/new_run.py --period period-004 --id period-004-page-harness-example --name "Page harness trial" --benchmark web-page-harness --type harness-integration --harness local-page-harness
& .local/bfcl-official-venv/Scripts/python.exe -B -X utf8 integrations/page_harness/run_probe.py --run period-004-page-harness-example --question "Your public research question here"
```

Use `--no-snippets` to withhold search snippets from the model; the complete SearXNG reply remains in the private run log. `--compact-fraction` changes the token threshold, and `--recent-turns` changes how many recent complete turns are protected. For the earlier character-triggered approach, explicitly use `--compaction-mode legacy --compact-chars 6000 --compact-keep 1`; those character options are rejected in model-compaction mode. Run offline tests with `& .local/bfcl-official-venv/Scripts/python.exe -B -m unittest discover -s tests -p 'test_page_harness*.py' -v`. Final-answer URL checking and the ledger do not verify that a quote, claim, or section number is correct. The caller must inspect evidence. This is a pilot harness, not an official BFCL adapter.

For saved runs, `audit_saved.py --run RUN_ID` creates a separate URL-exposure audit and `reconstruct_ledger.py --run RUN_ID` creates a separate ledger of read/find results; neither changes the original answers or events. A reconstructed ledger records tool-produced ranges and, especially in an unfinished case, does not by itself prove every range was presented to the model. Both refuse to replace an existing output. `evaluate_saved.py --run RUN_ID` applies the pinned BFCL answer-string checker to supported study inputs, but a substring match does not verify evidence or turn the pilot into an official BFCL score.
