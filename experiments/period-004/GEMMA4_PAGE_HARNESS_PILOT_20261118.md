# Gemma 4 E4B: ページ分割・読み直しハーネスの試験

ローカルハーネス `integrations/page_harness/` を追加。SearXNG MCPで検索し、結果のURLのみCrawl4AI MCPへ渡す。Crawl4AIの `md` と `read_document` から同一document IDの全断片を検証してローカル保存し、Gemmaには検索・見出し・ページ内の文字列検索・文字位置指定による再読を提供する。本文は未信頼データとする。文字数閾値を超えた場合、古い本文取得結果をページIDと位置への参照に置換し、元のツール応答・本文はrunに保存する。履歴圧縮は文字数ベースでありトークン上限の保証ではない。

保存ページの位置指定、再読、擬似ページネーションの不一致、擬似モデルとMCPでの呼び出し往復、履歴退避をオフライン検証。4件成功。ネットワーク利用は明示された実試験だけ。実行条件はGemma 4 E4B Q4_K_M、b11960、全GPU、MTP ON、Thinking ON、65,536 context、応答あたり最大8,192、temperature 0.6、seed 42。独自の公開資料2問で、BFCL公式評価ではない。MCPはSearXNG `2026.10.30+ffa88e3ba.local.4244dcfa4e4b`、Crawl4AI `0.9.5+local.4901cb2a4782`。各問題につき検索最大5、ページ最大4、read/find各15、20往復で、初回失敗の自動再試行なし。

| 問題 | 動作 | 結果 |
|---|---|---|
| Python jsonの例外・ensure_ascii | 検索1、開く1、本文read 2、ページ内find 3 | `JSONDecodeError`・`True`と回答し、Python公式URLを記載。3回の文字列検索は長い文字列の完全一致でヒットせず、2件目の値は検索結果の抜粋にも含まれていた。 |
| RFC 6585の429・Retry-After | 検索1、開く1、find 1 | 両方の事実は正しい。findが返した抜粋を使用。ただし回答の引用箇所を節7.2と誤記（当該文は節4）、URLも明示しなかった。 |

問題1のページ検索空振りと問題2の出典URL欠落を受け、以後のソース版では完全一致なしの場合の短い検索語の案内と、最終回答内に開いたURLがない場合の警告を追加した。警告は引用の正しさや節番号を検証するものではない。旧runの実行コードはrun内snapshotに保持。追加の異なるRFC 9110問題1問では、検索1・開く1・read 1でDELETEと9.3.5を回答し、読んだ二次サイトのURLを明記した。公式RFCの原典URLではない。

3問とも通常停止し、ページ内検索または保存済みページの部分を参照した。ただし元の文字列検索は意味検索ではない。実験では会話退避条件には達せず、コンパクションの実動作は模擬試験のみ。小数の独自問題からBFCL正答率向上や不正なページ指示への耐性を推定できない。さらに検索結果に含まれるURL以外は開かず、DNSの公開IPチェックは行うが、Crawl4AI側のリダイレクト先検証はこのハーネスから確認していない。

当初実験: `runs/period-004-gemma-mtp-page-harness-pilot-20261118/`。更新後の異なる1問: `runs/period-004-gemma-mtp-page-harness-followup-20261118/`。各runに質問、ツール引数・結果、実際のモデル応答、ローカル保存ページ、VRAMサンプル、コードsnapshotを残した。MTPあり本体の観測ピークGPUメモリは初回6,757 MiB。モデルサーバーをそれぞれ終了。
