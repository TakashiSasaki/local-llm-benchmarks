## 何を比較するか

「通常版から一般能力がどれほど変わるか」と「このPCで使う無検閲配布物としてどれが良いか」を分けます。追加学習・マージ・テンプレート・量子化が複合したモデルの改善を、拒否方向の除去だけの効果とは呼びません。上位という結論は、コード・ツール・推論・日本語・速度それぞれの観測から出します。

| 段階 | 新規の配布物 | 主能力回答数 | 目的 |
| --- | --- | ---: | --- |
| A | 通常4B / Abliterix4B | 400 | 安価な対照で採点・拒否判定・保存形式を検証 |
| B | 通常9B / Huihui9B / Heretic9B / Defiant9B | 800 | 同系統で手法と実用性能を比較 |
| C | 通常35B-A3B / Huihui35B-A3B | 400 | より高い能力を狙うMoE候補を比較 |
| 第一陣合計 | **8配布物（通常3＋改変5）、Q4_K_M、MTP OFF** | **1,600** | BFCL80＋HE20×思考OFF/ON、計32条件 |

主能力回答数には起動smoke・短文速度・過剰拒否・新規の数学/日本語問題・補助採点replayを足しません。通常9Bは各改変候補の比較で共有しますが、同じ回答を複数回の新規推論として数えません。第1期のBartowski/Unsloth対照を、新しいmradermacher対照の代用にしません。

## 0. 取得・実行前のゲート

1. 固定revision/bytes/SHA-256、配布元と元モデル、ライセンス、GGUF変換・量子化条件、既知の再アップロードを確認。選択ファイルの来歴が不明な場合は「配布物同士の比較」と明記。
2. ダウンロードはrepo外、1接続・再開可能・SHA照合で実施。第1期のモデルや取得途中ファイルを削除しない。不要な二重range結合や全候補の並列取得を避ける。
3. 各ファイルについてヘッダーとテンプレート、architecture、native context、MTP重みを確認し、既存b11960で短い起動/3短文/関数呼び出し・呼び出し不要・並列呼び出しをsmoke。思考要求と実際のreasoningを確認。これらは能力得点に含めない。
4. context64K/F16で容量を観測し、比較する通常/改変の双方で成立する配置を決める。RAM空き3 GiB・GPU余裕512 MiBを目標とする初期案で、稼働環境を見て測定前に固定。観測不能、OOM、guard作動は利用可否の結果として保存する。
5. 新しいGGUFが現runtimeで非対応の場合、runtime変更は別条件にする。更新だけで済ませず通常版も同じruntimeで再測定し、第1期との版差を残す。

native tool schemaを解釈できないものは「非対応/形式不適合」を示し、未実行80問を0/80として埋めない。独自アダプターが必要なら別試験。長い生成中でもtokenが増えていれば停止と判断しない。

## 1. 一般能力の主比較

- context **65,536**、1 slot、F16 K/V、最大出力 **64,000**、API待機 **7,200秒**。実入力長に応じた予約規則を保持し、入力/出力/context上限を別に記録。
- BFCLは第1期の固定80問・元の公式AST checkerと変換器・greedy/seed42。HumanEvalは同じ固定20問・temperature0.6等のrequest samplerとseed42。入力、順序、履歴/キャッシュ、配置、load-mode、threadsを対照内で揃える。
- HumanEvalの第2期主評価は**標準準拠の採点またはEvalPlusを固定・canonical検証してから**用いる。第1期の制限付き主採点は互換確認用の別replay列に残す。`type()`等による既知の誤失敗と本当の能力差を混ぜず、過去得点は上書きしない。
- 全配布物を思考OFF/ONで分ける。モデル固有テンプレートは記録し、強い独自system promptを候補の一つだけに足さない。Defiantはまず通常のnon-plusIQ Q4ファイルを選び、追加のreasoning modeやTOOLSテンプレートは別条件。
- MTPは最初OFF。量子化S/M/L、Q3/Q5/Q8、MTPの全直積を先に広げない。通常/改変で同一Q4名でもtensor構成や較正が違う場合は交絡として残す。

保存する指標は、得点と問題別の改善/悪化、拒否・形式エラー・空final・反復・cap、ツール必須60問とirrelevance20問、観測reasoning、既知token/不明統計、合計秒/応答分布/速度、メモリ標本、失敗/未実施条件です。BFCL採点上の「呼び出し0件で正解」を、最終回答や実ツール成功と同じにしません。

タイムアウトしたrunはそのまま保存し、無限リトライ・無断の出力上限増加はしません。原因を確認し、条件変更を試す場合は新run。実行時間はpreflightと最初のモデル対で見積もり直し、計画段階で楽観的な全体完了時刻を約束しません。

## 2. 拒否・推論・日本語を別評価

- 過剰拒否: [XSTest作者repo](https://github.com/paul-rottger/xstest)の**safe250問**を候補とし、拒否/部分応答/回答を分類して回答の適切さも確認。危険なcontrast200問とは分ける。安全な政治・歴史・創作等の日本語補足は別データにし、翻訳文と公式英語値を混ぜない。
- XSTestはrevision`d7bb5bd738c1fcbc36edd83d5e7d1b71a3e2d84d`の450行と250/200の内訳をメモリ上で照合済み。[metadata](research/xstest-metadata-20261102.json)にdigestとCC BY 4.0を保存。まだデータセット本体をrepoへ導入せず、モデルへの入力も行っていない。取得時に出典・ライセンスをversioned datasetへ保存する。
- 数学/一般推論: 固定GSM8K100問等を追加する。正答抽出を確認し、理由の長さや拒否率だけで推論性能を評価しない。上位候補＋その通常版から始める。
- 日本語: 固定した日本語理解/指示追従セットを導入し、機械採点可能な正解と人手確認を分ける。日本語を返しただけで高品質としない。データと採点基準は測定前に固定する。
- 差が小さい上位候補はHumanEval全164問＋EvalPlus追加testや複数seedで拡張する。20問では1問5ポイントのため、僅差で性能保持/優越を断定しない。

上記の拡張セットは**未実装・未測定**で、1,600回答に含めません。safe promptsだけの拒否率は無検閲の全般的な証明ではなく、正当な要求への過剰拒否を測るものです。

## 3. 実用速度・Hermes・MTP

能力比較の共通配置とは別に、各モデルで安全にGPU搭載を増やした配置を保存し、固定256 tokens×3 prompts×3回の速度を比較します。CPU MoE層数とdecoder層全体のCPU配置を混同しません。短文の速度改善を数万tokenの思考に一般化しません。

上位1〜2候補と対照で、Hermesのread_file→terminal→write_fileを別runで確認し、正しい引数・実tool結果・入力維持・生成物の検算を保存します。BFCLの点数だけで接続成功としません。

MTPはその後の補足です。重みがあるGGUFで実draft数を確認し、**同じMTP対応ファイルのOFF/ON**を比較します。MTPなしファイルとMTPありファイルの結果差を、そのままスイッチだけの効果とは呼びません。`/props`の既定値だけで判断せず、受理率・速度・品質・追加メモリを残します。

## 4. 第二陣と容量予算

第一陣の新規取得は**71,613,011,104 bytes（71.61 GB、約66.70 GiB）**。現在の空き146.1 GBから取得後は約74.5 GBとなり、32 GiB予約を確保できる見込みです。ウェイト本体と`.part`のrenameで済ませる1接続を基本にし、二重コピーを予算へ隠さない。取得直前にも空きを再確認します。

追加のQwen3.8通常/27B RVN multilingual対は**33,358,115,072 bytes（33.36 GB）**。第一陣と全て保持すると残り約41.1 GB（約38.3 GiB）で、32 GiB予約に対する余裕は小さくなります。さらにDolphin24B対やQ8対を同時追加する前に予算を見直します。既存モデルや原結果の削除を前提に進めません。

優先追加は27B RVNの絶対能力、別方式ならDolphin24B v1.2、系列を広げるならGemma4ですが、各々対照・来歴・容量・速度のゲートを満たしてからです。NeuralDaredevil等の8K/32Kモデルは共通の短いcontextで別比較にし、64K拡張を黙って適用しません。
